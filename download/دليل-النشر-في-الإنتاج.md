# دليل نشر نظام مطعم التكية في الإنتاج

هذا الدليل يشرح كيفية نشر النظام في بيئة إنتاجية آمنة وقابلة للتوسع.

## المتطلبات

- Node.js 20+ أو Bun
- PostgreSQL 14+ (موصى به) أو SQLite للتطوير
- مساحة قرص 1GB+ للنظام والصور
- اتصال إنترنت مستقر

---

## 1. النشر على Vercel (الأسهل - مجاني)

### الخطوة 1: إعداد قاعدة بيانات PostgreSQL

استخدم أحد الخدمات المجانية:
- **Neon** (موصى به - neon.tech) - مجاني حتى 10GB
- **Supabase** (supabase.com) - مجاني حتى 500MB
- **Railway** (railway.app) - تجربة مجانية

احصل على رابط الاتصال، مثل:
```
postgresql://user:password@ep-xxx.us-east-2.aws.neon.tech/dbname?sslmode=require
```

### الخطوة 2: تحديث ملف Prisma

في `prisma/schema.prisma`، غيّر:
```prisma
datasource db {
  provider = "postgresql"  // بدلاً من "sqlite"
  url      = env("DATABASE_URL")
}
```

ثم شغّل:
```bash
bun install
bun run db:push
```

### الخطوة 3: رفع المشروع إلى GitHub

```bash
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/username/restaurant-system.git
git push -u origin main
```

### الخطوة 4: النشر على Vercel

1. اذهب إلى [vercel.com](https://vercel.com)
2. انقر "New Project"
3. اربط مستودع GitHub
4. أضف متغيرات البيئة:
   - `DATABASE_URL` = رابط PostgreSQL
5. انقر "Deploy"

ستحصل على رابط مثل: `https://mataam-tekiya.vercel.app`

## 2. النشر على VPS (تحكم كامل)

### متطلبات الخادم:
- Ubuntu 22.04+ أو Debian 12+
- 1GB RAM على الأقل
- 20GB مساحة قرص

### الخطوة 1: تثبيت المتطلبات

```bash
# تثبيت Node.js 20
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs

# تثبيت Bun
curl -fsSL https://bun.sh/install | bash

# تثبيت PostgreSQL
sudo apt install -y postgresql postgresql-contrib

# تثبيت Caddy (لـ HTTPS تلقائي)
sudo apt install -y caddy
```

### الخطوة 2: إنشاء قاعدة بيانات PostgreSQL

```bash
sudo -u postgres psql
```

```sql
CREATE USER tekiya_user WITH PASSWORD 'strong_password_here';
CREATE DATABASE tekiya_db OWNER tekiya_user;
GRANT ALL PRIVILEGES ON DATABASE tekiya_db TO tekiya_user;
\q
```

### الخطوة 3: نسخ المشروع

```bash
sudo mkdir -p /var/www/restaurant
sudo chown $USER:$USER /var/www/restaurant
cd /var/www/restaurant
# انسخ ملفات المشروع هنا
```

### الخطوة 4: إعداد ملف البيئة

```bash
cat > .env << 'EOF'
DATABASE_URL=postgresql://tekiya_user:strong_password_here@localhost:5432/tekiya_db
EOF
```

### الخطوة 5: تحديث Prisma للـ PostgreSQL

في `prisma/schema.prisma`:
```prisma
datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}
```

ثم:
```bash
bun install
bun run db:push
```

### الخطوة 6: البناء والتشغيل

```bash
bun run build
# تشغيل بـ PM2 لإدارة العملية
sudo npm install -g pm2
pm2 start "bun .next/standalone/server.js" --name restaurant
pm2 startup
pm2 save
```

### الخطوة 7: إعداد Caddy (HTTPS تلقائي)

```bash
sudo nano /etc/caddy/Caddyfile
```

أضف:
```
yourdomain.com {
    reverse_proxy localhost:3000
}
```

ثم:
```bash
sudo systemctl restart caddy
```

Caddy سيحصل على شهادة SSL مجانية تلقائياً.

## 3. إعداد النسخ الاحتياطي التلقائي

### على VPS (cron job يومي):

```bash
# تحرير crontab
crontab -e
```

أضف السطر التالي للنسخ الاحتياطي يومياً الساعة 2:00 صباحاً:
```
0 2 * * * cd /var/www/restaurant && bun run backup >> /var/www/restaurant/backups/backup.log 2>&1
```

### نسخ احتياطي على Vercel:

استخدم Vercel Cron Jobs (ملف `vercel.json`):
```json
{
  "crons": [
    {
      "path": "/api/backup",
      "schedule": "0 2 * * *"
    }
  ]
}
```

أو استخدم خدمة خارجية مثل:
- **Upstash** للنسخ الاحتياطي المجدول
- **GitHub Actions** للنسخ إلى التخزين السحابي

---

## 4. الأوامر المفيدة

| الأمر | الوصف |
|---|---|
| `bun run backup` | إنشاء نسخة احتياطية فورية |
| `bun run restore` | عرض النسخ المتاحة للاسترجاع |
| `bun run restore backup-2026-11-23-12-03-25` | استرجاع نسخة محددة |
| `bun run audit` | عرض إحصائيات سجل الأحداث |
| `bun run db:push` | تحديث قاعدة البيانات بعد تغيير الـ schema |
| `bun run lint` | فحص جودة الكود |

## 5. فحوصات ما بعد النشر

بعد النشر، تأكد من:

- [ ] الموقع يفتح على HTTPS (القفل الأخضر في المتصفح)
- [ ] تسجيل الدخول يعمل بشكل صحيح
- [ ] النسخ الاحتياطي يعمل (`bun run backup`)
- [ ] سجل الأحداث يسجل العمليات (تبويب "سجل الأحداث")
- [ ] Rate Limiting يعمل (جرّب 6 محاولات دخول خاطئة)
- [ ] رفع الصور يعمل
- [ ] QR Code يحتوي على الرابط الصحيح

## 6. استكشاف الأخطاء

### المشكلة: قاعدة البيانات لا تتصل
- تأكد من `DATABASE_URL` في ملف `.env`
- تأكد من أن PostgreSQL يعمل: `sudo systemctl status postgresql`
- تأكد من الصلاحيات: المستخدم يمكنه الوصول للقاعدة

### المشكلة: الصور لا تُرفع
- تأكد من أن مجلد `public/uploads/` له صلاحيات الكتابة
- على VPS: `sudo chown -R www-data:www-data public/uploads`

### المشكلة: Rate Limiting يحجب المستخدمين الشرعيين
- الـ Rate Limiting في الذاكرة فقط، يُمسح عند إعادة التشغيل
- للإنتاج متعدد الخوادم، استخدم Redis بدلاً من الذاكرة

### المشكلة: النسخ الاحتياطي يفشل
- تأكد من وجود مساحة كافية على القرص
- تأكد من صلاحيات الكتابة على مجلد `backups/`

## 7. الترقية المستقبلية

عند الوصول للحدود التالية، يجب الترقية:

| المؤشر | الحل |
|---|---|
| أكثر من 1000 فاتورة يومياً | أضف Redis للتخزين المؤقت |
| أكثر من 50 مستخدم متزامن | أضف Load Balancer + خوادم متعددة |
| أكثر من 10GB بيانات | أرشف الفواتير القديمة |
| بطء في الاستجابة | أضف CDN للصور (Cloudflare) |
| هجمات أمنية | أضف WAF (Web Application Firewall) |

## الدعم

1. سجل الأخطاء: `tail -f dev.log` أو `pm2 logs restaurant`
2. سجل الأحداث الأمنية في تبويب "سجل الأحداث"
3. النسخ الاحتياطية في مجلد `backups/`
